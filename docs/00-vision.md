# 00. ビジョン

## 解こうとしている問題

音源を持っている人が「この音をこういう感じに変えたものが欲しい」と思ったとき、現状の選択肢は次のどれかになる。

- サンプラーに読み込む → 元の音の変形はできるが、音の**構造**は変えられない
- 既存シンセで似た音を自力で作る → 高度な音作りの技能と時間が要る
- プリセットを漁る → 目的の音がある保証がない

本プロジェクトは、この間を埋める。音源と言葉による意図を入力に、**その音を再現できるシンセパッチを生成し、かつ生成後もDAW上で演奏・調整・オートメーションできる形で手渡す**。

## なぜサンプル再生では足りないか

ワンショットサンプルの再生では、ユーザーが想像している「変えた音」に到達できない。到達に必要な要素が、サンプルという表現形式の中に**分離可能な形で存在していない**からである。

- アタック部のノイズは、時間変化するスペクトル包絡であって、単一の値ではない
- フォルマントは共振ピークの周波数・帯域幅・ゲインの組であり、独立に動かせなければ「声質を変える」ができない
- 音程間の遷移やモジュレーションは値ではなく時間の関数であり、静的なサンプルには畳み込まれてしまっている

これらを独立に操作可能にするには、サンプルを加工するのではなく、**同等の音を生成できるシンセエンジンにフィッティングする**必要がある。これが本プロジェクトの中核的な主張である。

## 成功の定義

3つの水準で定義する。

### 水準1：再現（フィット）
与えたターゲット音源に対し、生成されたパッチのレンダ結果が、指標上あらかじめ定めた閾値内に収まる。閾値は `docs/04-metrics.md` で定義する（現時点では未確定）。

### 水準2：操作性
生成されたパッチが、DAWに露出されたマクロ軸の操作だけで、音楽的に意味のある方向へ連続的に変化する。パラメータを動かすと壊れる、という状態は失敗とみなす。

### 水準3：到達
ユーザーが脳内にある音に、実用的な試行回数（目安：10回以内の対話）で到達できる。

水準1は自動測定できる。水準2は半自動。**水準3は測定できない**ため、到達失敗の履歴を蓄積して定性的に評価する（`docs/log/capability-gap-log.md`）。

## Non-goals

以下は本プロジェクトの目標ではない。混同すると設計が発散する。

- **汎用の音源分離・ステム抽出**：入力は単一音色を想定する
- **リアルタイムでの音色推定**：フィッティングはオフラインで行う
- **既存プラグインの自動操作**：自前エンジンを持つ方針を採る。理由は `docs/adr/0002` 参照
- **エンドツーエンドのニューラル音声生成**：出力はDAWで操作可能なパラメータでなければならないため、ブラックボックス生成は採らない

## フェーズと遷移条件

| フェーズ | 内容 | 次へ進む条件 |
|---|---|---|
| **0. ハーネス** | レンダ→指標算出のパイプライン、ゴールデン音源セット整備 | 指標ベクトルがCIで自動出力される |
| **1. 最小エンジン** | 4層構成の最小実装（`docs/02`） | ゴールデン音源1つに対し手動でパラメータを与えてレンダできる |
| **2. フィッティング** | 分析→パラメータ推定→プリセット生成の内側ループ | コーパスに対し自動でフィットが回り、指標が収束する |
| **3. 仕様改訂** | 残差プロファイルからエンジン能力を改訂する外側ループ | コーパス全体の残差が閾値内に入り、改訂が収束する |
| **4. マクロ設計** | 内部パラメータからDAW露出軸への写像設計 | 水準2を満たす |
| **5. 対話** | 意図からの変換、A/B弁別による選好抽出 | 水準3の評価が始められる |

**フェーズを飛ばさないこと。** 特にフェーズ0を飛ばして1に入ると、以後すべての作業でエビデンスが出せなくなる。

### フェーズ2に持ち越す既知の限界

遷移条件が要求しているのは「手動のパラメータでレンダできること」であって「フィットできること」「指標値がターゲットへの近さとして信頼できること」ではない。以下は未達のままフェーズ2に持ち越す。**フェーズ1が完了したことを、フィッティングが機能することや指標値が信頼できることの根拠に使ってはならない。**

- **フィット済みプリセットは存在しない。** P1-12 のプリセットは `spoken_hello` 1音源に対する手書きの1つであり、残る10音源は共通の暫定プリセット（`corpus/presets/provisional_v0.json`）でレンダしている。指標値はフィットの誤差を表さず、成功判定の閾値（Q-002）も未設定である。層実装PRでコーパス指標の悪化を合否に使わないとした Q-013 の暫定は、妥当性をフェーズ2で検証するため open のままであり、`AGENTS.md` 第6節の悪化禁止はフィット済みプリセットが用意された時点から再び適用される（Q-013「暫定の扱い」3・4）
- **区間別指標の遷移部・定常部・リリースは全音源で欠測である。** `corpus/baseline/` の全11音源で、この3区間の指標がすべて欠測になっている。区間境界の注釈が未付与のため（Q-009）。注釈の付与は P1-13（#58）で行う
- **区間別指標のアタック区間は、既定のアタック窓 [0, 20ms) の妥当性が実測で否定されている（Q-009、#105）。** ゴールデン音源11件中7件で、既定窓はオンセットより前にある。うち3件（`violin_pizzicato`・`violin_vibrato`・`crash_cymbal`）は target の窓内が全標本0で、`corpus/baseline/` のアタック区間指標が3件とも同一値（`msstft` 36.989、`mfcc` 1280.457、`loudness_diff_db` 248.458）になっている。アタック終端の正解を観測する手段がなく、Q-009 は resolved にできていない。**現行のアタック区間指標を残差の切り分け（`docs/01-architecture.md`）の根拠に使ってはならない**（Q-009「暫定の扱い」）。Q-009 が要求する観測（フィット済みプリセットで Transient 層をオン/オフしてレンダし残差の時間範囲を見る）はフィット済みプリセットの存在を前提とするため、フェーズ2で扱う
- **target のオンセットと candidate のノートオンの時間整列は、規約だけが決まり、未適用である（Q-019、resolved〈ADR-0012〉）。** target には長い先頭無音・低振幅区間を持つ音源があり（−40dBオンセットが `spoken_hello` で約222ms、`violin_pizzicato` で約728msなど）、現行の指標算出は target と candidate を同じ絶対時刻で比較するため、このずれは音色差と分離できないまま全体指標・区間別指標・軌跡指標のいずれにも誤差として入りうる。ADR-0012 で、整列はハーネスが持ち、所有者が付与したずらし量で target のずらし量より前を比較から外すと決めた。ずらし量の付与とハーネスでの適用（上記の3つの Issue）が済むまで、この誤差は残る
- **`corpus/baseline/` の鮮度検証（#88）が、同じコードに対して pass と fail に割れた実測があった（#96、解消済み）。** PR #92 の pull_request 実行（head `73c435f`）と main への push 実行（`b5f79a2`）は、`corpus/` `engine/` `harness/` 配下に差分がなく、ランナーイメージも同じ `ubuntu24/20260831.293` だったが、前者は `stale: 0`、後者は `stale: 10` になった（#96 に記録された差は指標値の最終1〜2桁）。その後の main（`5a944a4`、イメージ `ubuntu24/20260907.300`）では `stale: 0` だった。**原因の切り分けは `docs/adr/0008`「8.」で決定した。** ハーネスが算出する指標値は、マシン（CPU）をまたいだビット一致を保証しない。NumPy / OpenBLAS が実行時にCPUに応じて演算カーネルを選び、その選択だけで `transient_env_corr` 等の最終桁が変わる機構がローカルで再現できた（CIの1値をビット単位で再現）。ただし `f0_dist`・`segments.attack.loudness_diff_db` の差はこの機構では再現せず、原因は未特定のまま残る。失敗 run（34055105958）が実際にどのCPUで動いたかもログに出ておらず未確認。この決定を受け、鮮度検証の判定方式はビット完全一致から許容誤差付き比較（`math.isclose(rel_tol=1e-12, abs_tol=1e-12)`）に変わった。実装は #108・PR #110（マージ済み）。#96 は PR #110 でクローズされた
- **暫定値のまま進んでいるものがある。** いずれも open であり、フェーズ2の観測で確定・変更する
  - Q-004：スペクトル包絡の帯域分割（Transient 層は周波数等間隔を暫定採用。`docs/adr/0009`）
  - Q-014：レンダ長の導出（プリセット内の時間軸の最大値と `transient.duration` の大きい方）
  - Q-015：バージョン対応（`0.1.0` との厳密一致のみ）
