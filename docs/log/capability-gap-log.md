# 能力ギャップログ

ループ2への入力を蓄積する。**入力経路は2本あり、性質が違う**（`docs/01-architecture.md`）。

- **経路A（数値）**：ループ1が能力ギャップと判定した残差プロファイル。自動追記される
- **経路B（言語）**：ループ3でユーザーが到達できなかった履歴。自動判定できないため、人間が定期的に読む

**単発のエントリで仕様を改訂しないこと。** コーパス横断で同じ傾向が出て初めて改訂の根拠になる。

---

## 経路A：残差プロファイル

```
### GAP-A-NNN
- 日付：
- ターゲット：
- 反復回数：
- 残差が偏った位置：（区間 / 帯域 / 軌跡）
- 疑われる不足層：
- 同じ傾向を示した他のターゲット：
- 状態：observed / confirmed / addressed（ADR番号）
```

（エントリなし）

---

## 経路B：到達failure

```
### GAP-B-NNN
- 日付：
- ユーザーが求めた方向（原文のまま記録すること）：
- 提示した候補と選択：
- 何周して打ち切ったか：
- 推定原因：マクロ軸の設計ミス / エンジンの能力不足 / 判定不能
- 状態：observed / confirmed / addressed（ADR番号）
```

**ユーザーの言葉は要約せず原文で記録する。** 要約すると、語彙と軸の対応（Q-007）を後から獲得できなくなる。

（エントリなし）
