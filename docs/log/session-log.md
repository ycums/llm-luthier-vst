# セッションログ

作業中に起きた失敗・手戻りを記録する。`AGENTS.md` 第7節の「3回ルール」の根拠となる。

**スキル化やCIチェック追加の提案は、このログのエントリを引用して行う。** 根拠のない「あったら便利そう」は却下される。

```
### S-NNN
- 日付：
- 何をしようとしたか：
- 何が起きたか：
- 手戻りの規模：
- 分類：（後で集計するためのタグ。例：仕様の曖昧さ / 環境構築 / 指標の欠落 / レビュー漏れ）
- 同じ分類の過去エントリ：
```

同じ分類が3件たまった時点で、対処（スキル化 / CIチェック追加 / ドキュメント修正）を提案する。

### S-001
- 日付：2026-09-05
- 何をしようとしたか：エージェントがIssue対応のPRを作成
- 何が起きたか：PR本文に対応Issueへの参照は書かれたが、GitHubのクローズキーワード（Closes/Fixes/Resolves）ではなかったため、マージしてもIssueが自動クローズされず、ユーザーが手動でIssueをクローズする羽目になった
- 手戻りの規模：小（手動クローズ1回）
- 分類：PRテンプレート/Issueクローズ漏れ
- 同じ分類の過去エントリ：なし
- 対処：PRテンプレートの「対応Issue: #」を「Closes #」に変更し、AGENTS.md 第10節にクローズキーワード使用を明記（1回目の発生だが、テンプレート文言自体の不備が直接原因のため即時修正。3回ルールはCIチェック等の追加機能に適用し、既存テンプレートの誤りの是正には適用しない）
