# 02. エンジン能力仕様 v0

> **このドキュメントは改訂前提の暫定版である。**
> v0は「正しい設計」ではなく、**ループ2を回し始めるための最小の出発点**である。
> 最初の数周で「エンジンが足りない」という結論しか出ないのは正常な挙動であり、失敗ではない。
> 改訂は必ずADRを伴うこと（`docs/adr/`）。

## 設計順序についての注意

分析手法を先に決めてエンジンを後から合わせる、という順序を採ってはならない。分析側は時間変化する多次元データを吐くのに、受け皿が静的なスカラーの集合だと情報の大半が捨てられる。

**エンジンの自由度（パラメータ空間の種類と次元）を先に確定し、そこに合わせて分析手法を選ぶ。** いわゆる analysis-by-synthesis の順序である。

## 層構成

v0では4層を置く。各層は独立に有効／無効にでき、レンダ時に加算合成される。

```
[1] Transient / Noise 層  ──┐
[2] Harmonic / Body 層    ──┼─→ [3] Formant filter bank ─→ out
                            ┘
        ↑ すべてのパラメータが
        └── [4] Modulation matrix から変調可能
```

### [1] Transient / Noise 層

アタック部を専任で担当する。ワンショットの印象を決定づける領域であり、単一のノブでは表現できない。

| パラメータ | 型 | 備考 |
|---|---|---|
| `spectral_envelope` | 時系列（ブレークポイント列 × 帯域） | 時間変化するスペクトル包絡 |
| `duration` | scalar (ms) | |
| `gain` | scalar (dB) | |
| `seed` | int | ノイズの再現性確保のため |

帯域数・ブレークポイント上限は未確定（`docs/06-open-questions.md`）。

### [2] Harmonic / Body 層

定常部の倍音構造。v0では加算合成とウェーブテーブルのどちらを採るかを未確定とし、**インタフェースだけ先に切る**。

| パラメータ | 型 | 備考 |
|---|---|---|
| `f0` | 時系列 | 基本周波数の時間変化。グライドはここで表現する |
| `partial_amplitudes` | 時系列 × N倍音 | |
| `inharmonicity` | scalar | 非整数次倍音のずれ |

### [3] Formant filter bank

共振ピークの組。**声質・楽器の胴鳴りを独立に操作できるようにするための層**であり、単純なEQでは代替できない。

- バンド数：v0は 4（3〜5の範囲で改訂を想定）
- 各バンドが持つもの：`freq` / `Q` / `gain`、いずれも**時系列**

各バンドのパラメータが時間変化できることが必須要件である。静的にするとフォルマント遷移が表現できず、母音変化や奏法変化を再現できない。

### [4] Modulation matrix

上記すべてのパラメータへ、変調源をルーティングできる構造。

- 変調源：Envelope（ブレークポイント列）、LFO（波形／レート／深さ／同期）
- ルーティング：source × destination の疎行列。深さとカーブを持つ
- v0での上限：source 4 × destination 8

構造の参考として AIR OPx-4 / FM8 型の自由マトリクスを想定する。アルゴリズム選択型（DX7型）は自由度が足りない。

## 何が v0 で意図的に欠けているか

以下は「忘れている」のではなく「観測してから決める」ために保留している。ループ2で残差プロファイルを見て必要性が示されたときに追加する。

- ユニゾン／デチューン
- 非線形歪み（サチュレーション）
- 空間系（リバーブ、ディレイ）
- レイヤー数の拡張（現状は各層1インスタンス）
- ベロシティ／キーによるパラメータスケーリング

## 実装上の制約

- **エンジンコアはプラグインフレームワークに依存しない層として切り出す。** VSTプラグインとヘッドレスCLIレンダラが同一コアを共有するため（`docs/01-architecture.md`）
- レンダは決定論的であること。同じプリセット・同じseedから常にビットレベルで同一のWAVが出ること。CIリグレッションが成立しなくなるため必須
- サンプルレート非依存であること

## DAW露出パラメータについて

このドキュメントに列挙したのは**内部パラメータ**であり、DAWに露出するものではない。露出するマクロ軸の設計はフェーズ4で行う（`docs/00-vision.md`）。現時点でマクロ軸を設計してはならない。
