## Q-016. P1-08 の層実装で採った暫定値（interp の規約・inharmonicity 式・倍音数上限・決定論の範囲）
- **何が不明か**：`docs/03` が定めるのは interp の種類名（linear/exp/step/spline）と「点が1個で定数」までであり、以下は仕様に未記載だった。P1-08（#53）は「仕様に無いものを推測で埋めず、暫定値を置いて記録する」（`AGENTS.md` 第7節）に従い、次の暫定値を取り、それを実装とこのエントリの両方に反映した。
  1. **interp の挙動**：t が最初の点より前・最後の点より後では端点の値をそのまま返す（定数外挿）。`exp` は対数域での線形補間（幾何平均 `v0*(v1/v0)^u`）、ただし端点のいずれかが非正の場合は線形に縮退。`spline` は自然3次スプライン（両端の2階微分=0）。
  2. **inharmonicity 補正式**：`freq_k = f0 * k * (1 + inharmonicity * (k - 1))`（k=1は補正なし）。`docs/adr/0007` は「補正式自体はP1-08の実装詳細」と委譲しており、式は本エントリの暫定値。
  3. **partial_amplitudes の倍音数上限**：`docs/03`「未確定」。v0では**上限を設けない**（発振器数＝`partial_amplitudes` の配列要素数）。レンダラの存在を前提とする観測（コーパスで実際に必要な倍音数）をしてフェーズ2で決めるため、本Issueでは暫定として上限なしを採る。
  4. **決定論の範囲**：`docs/02`「同じプリセット・同じseedから常にビットレベルで同一のWAV」を、**同一バイナリ内のビット一致**（同じビルド・同じ環境での再現性）として満たす。`std::sin` の計算は規約上コンパイラ（libm）をまたいで最終桁が異なりうるため、**コンパイラ間（gcc/MSVC）のビット一致は保証しない**。解析検証テストは絶対誤差 1e-6 で判定する（コンパイラ間の libm 差異 ~1e-15 に対して十分小さく、実装誤りとは明確に区別できる）。CI は各環境で独立に解析検証をする（#66 のサポート対象＝CI検証対象）。
- **何が決まれば検定できるか**：フェーズ2でフィット済みプリセットが揃い、(3) の倍音数上限（実測の必要倍音数）と、コーパス指標を見て (2) の補正式の妥当性を評価できる。
- **状態**：open（P1-08の実装詳細としての暫定であり、フェーズ2の観測で確定・変更する）。
## Q-017. Formant filter bank の構成（並列バンク vs 直列カスケード）と決定論の保証範囲
- **何が不明か**：`docs/02-engine-spec.md` 層[3]「Formant filter bank」は、4バンドが「並列（各バンドの出力を加算）」か「直列（カスケード）」かを明示していない。また `docs/adr/0006` の決定論方針（スカラーループで自動ベクトル化・FMA依存を避ける）が「同一バイナリ内の再実行のみ保証」か「コンパイラをまたいでビット一致まで保証する」かの範囲が明示されていない
- **何が決まれば進めるか**：
  1. バンドの接続方式。これは音響的な挙動（各バンドの `gain` の独立性、`gain:0` の切断の意味）を変える。並列なら各バンドが独立に効き `gain` も独立。直列（共振器の連鎖）は古典的なフォルマント合成に近く、あるバンドの `gain` を0にすると全体を通滅する
  2. 決定論の保証範囲。コンパイラの既定最適化（MSVC/Clang の `-O2`、GCC の FMA 縮約）や `std::tan` の libm 実装差が、再帰フィルタの丸め誤差を時間方向に蓄積させるため、**コンパイラをまたいだビット一致は現実的に成立しない**
- **決めるために必要な観測**：ループ2でコーパス残差を見て、並列と直列のどちらが残差を素直に減らすか。決定論の範囲は `docs/adr/0006`・`docs/adr/0008` の適用方針（同一コミットに対する同一環境での再実行の決定性を CI のリグレッションテストで担保する）で周知一致
- **暫定の扱い（P1-10 #55）**：
  1. **並列バンクを採用**：各バンドは TPT 状態変数バンドパスを1個持ち、全バンドの出力を加算する。各バンドの `freq` / `Q` / `gain` が独立に効くことをテストで保証する（Issue #55 完了条件）。直列カスケードとの差はループ2で観測してから改定
  2. **決定論は「同一ビルド・同一環境での再実行」を保証し、コンパイラをまたいだビット一致は保証しない**。`test_formant` の bit-identical テストで担保する。実装はスカラーループで書き、積極的最適化フラグは追加しない（`docs/adr/0006` を踏襲）。コンパイラまたいだビット一致が必要になった場合は ADR を改定して決める
- **状態**：open

## Q-018. 変調の適用式（source 値がどう目的地のパラメータ値に作用するか）
- **何が不明か**：`docs/02-engine-spec.md` は変調源（Envelope / LFO）とルーティングの存在だけを定義し（「source × destination の疎行列。深さとカーブを持つ」）、**source の値がどう目的地のパラメータ値に作用するか**（加算か乗算か、深さとカーブの意味）を定義していない。`docs/03-preset-format.schema.json` の `modulation_route.depth` / `.curve` にも値域・動作の規定はない
- **何が決まれば進めるか**：ループ2でコーパス残差を見て、加算方式に対する実際の要求（レベルの相対変化のみで十分か、f0 への乗算型変調が必要か）が判明する。`curve` の exp/step/spline が何を意味するかも、需要が出た時点で決める
- **暫定の扱い（P1-11 #56）**：所有者の承認により**加算方式**を採った。`dest(t) = base(t) + mod(t)`、ただし `mod(t) = source(t) × route.depth`。
  1. **LFO**：波形を `2π·rate·t` の位相で [-1,1] に正規化し、LFO 自身の `depth` を乗算（source 値の一部）。`sync` はヘッドレス v0 ではノートオンが常に 0.0 から始まり tempo/clock が存在しないため位相に影響しない。波形は v0.1 では `sine` / `triangle` / `square` / `saw` をサポートし、未知の波形は PresetError
  2. **Envelope**：ブレークポイント列を linear 補間し、範囲外は定数外挿
  3. **curve**：v0.1 では `linear` のみ対応。exp/step/spline は適用式が未定義のため PresetError で停止する（黙って線形近似しない）
  4. **destination の単位**：変調量は目的地の値域に加算される。`freq`/`f0`/`q` はそのまま Hz / 無次元、`*_db`（transient.gain / formant gain / spectral_envelope）は dB 値に加算してから振幅へ変換
  5. **transient.duration は時間変調の対象外**：レンダ長そのものを決めるパラメータに時間変調を掛けると「各サンプルの長さ」が不定になり正当な適用が定義できないため PresetError で弾く（routing の「パス存在」検証とは別の意味検証、`validateModulatableDestinations`）
  6. **無効な層へのルート**：変調先の層が `enabled: false` のとき、その層は出力に寄与しない（既存の層ゲート）ため、変調しても音には現れない。これは「無効層を変調が有効化しない」という仕様の明示であり、テストで検証する
- **状態**：open（フェーズ2の観測で確定・変更する）
