# 0003. ハーネスの実行環境と依存ライブラリ

- **状態**：Accepted
- **日付**：2026-09-05

## 背景

`docs/04-metrics.md` が定義する評価ハーネス（フィッティングの評価器とCIリグレッションテストを兼ねる）を実装するには、まず実装言語・ランタイム・外部ライブラリを決める必要がある。`AGENTS.md` 第5節により外部ライブラリの追加はADRと承認を要するため、これを済ませないと以降のすべての実装Issue（P0-02〜P0-14）が「未承認のライブラリを使った実装」になってしまう。

対象はハーネス（`docs/01-architecture.md` の責務分担表でいう「ハーネス（スクリプト）」行）のみである。エンジン本体（バイナリ、C++等）はフェーズ1の範囲でありスコープ外。

選定条件（Issue #1 補足より）：帯域別指標（`docs/04-metrics.md`）は Q-004（等間隔／メル／バーク）が未解決のため、**メル分割しか提供しないライブラリ／実装方式を選んで選択肢を先に潰さないこと**。

## 検討した案

### 実装言語・ランタイム

#### 案A：Python（採用）
- 利点：NumPy/SciPyを中核とする科学計算エコシステムが厚く、STFT・MFCC・YIN・スペクトログラム描画のいずれも実績のある実装が揃っている。CI（Linux runner）での自動化も容易。イテレーション速度が速く、フェーズ0の目的（指標算出とCIリグレッション）に対して実行速度よりも優先すべき性質と合致する
- 欠点：エンジン本体（C++等）とは別言語になり、境界（中間プリセット・レンダ済みWAV）を明示的なファイルI/Oで結ぶ必要がある。ただし `docs/01-architecture.md` は元々「ハーネス（スクリプト）」と「バイナリ（C++等）」を別の担当行として分けており、同一言語を要求していない

#### 案B：C++（エンジンと同一言語に揃える）
- 利点：エンジンと言語を揃えられる。実行速度が速い
- **却下理由**：音声分析（MFCC・YIN・フォルマント推定・スペクトログラム画像出力）の成熟したオープンソース実装がPythonほど揃っておらず、自前実装のコストが非常に大きい。ハーネスはCIで指標を出すことが目的でありレンダのような実時間制約はないため、実行速度を優先する理由がない

#### 案C：Rust
- 利点：速度と安全性
- **却下理由**：MFCC・YIN・フォルマント推定等の音声分析クレートが成熟途上で、C++案と同様に車輪の再発明コストが高い。ビルド待ち時間もイテレーション速度を下げる

#### 案D：MATLAB
- 利点：信号処理ツールボックスが豊富
- **却下理由**：商用有償ライセンスであり、CI環境での自動実行・誰でも再現できる開発環境という配布方針と矛盾する

#### 案E：Node.js / TypeScript
- **却下理由**：MFCC・YIN等の音声DSPの成熟したライブラリが乏しく、車輪の再発明が必要

### 外部ライブラリ

#### 帯域別指標（Q-004）の実装方式
mel専用のフィルタバンク関数（例：`librosa.filters.mel`）にそのまま依存すると、bark分割や任意の帯域端を後から選べなくなる。そのため帯域別指標は、STFTの振幅スペクトルに対して**帯域端（Hz）でビンを直接集計する自前実装**とする。等間隔・メル・バーク・任意の帯域端のいずれも、帯域端のリストを変えるだけで対応でき、特定のライブラリの分割方式に縛られない。MFCCはアルゴリズム定義上メル尺度が標準であるため、そこは案の通りmel実装（下記）を使う。

#### 案F：Essentia（却下）
- 利点：MFCC・YIN・スペクトル系の指標がまとまって提供されている
- **却下理由**：フリー版はAGPLv3であり、リポジトリの配布方針（誰でも自由に再利用できる状態を想定）と衝突しうる。加えてC++ライブラリのビルド・配布が絡み、pip一発でクリーンインストールできない

#### 案G：aubio（YIN実装、却下）
- 利点：YINを含むピッチ推定に特化
- **却下理由**：GPLv3。permissiveなライブラリ群の中でここだけ強いコピーレフトになり、将来の配布方針と矛盾するリスクがある

#### 案H：torchaudio / PyTorch（却下）
- 利点：MFCC等の音声特徴量が揃っている
- **却下理由**：GPU学習を前提とした重量級の依存で、インストールサイズ・依存関係の複雑さが本用途（オフラインの決定論的指標算出）に見合わない。フィルタバンクもmel専用

#### 案I：parselmouth（Praatラッパー、却下）
- 利点：フォルマント推定に定評がある
- **却下理由**：PraatはGPLv2ベース。案Gと同じ理由で却下。フォルマント軌跡距離（P0-09）は暫定方式で実装する方針（Issue #15）であり、フェーズ0時点で導入する必要がない

## 決定

### 実装言語・ランタイム

**Python 3.11 以上**（案A）を採用する。

### 外部ライブラリ

| ライブラリ | 用途 | ライセンス | バージョン制約 |
|---|---|---|---|
| numpy | 配列演算・FFTの基盤 | BSD-3-Clause | `>=1.26` |
| scipy | 信号処理（フィルタ、リサンプリング等の補助） | BSD-3-Clause | `>=1.11` |
| soundfile | WAV等音声ファイルの決定論的な読み書き（libsndfileラッパー） | BSD-3-Clause | `>=0.12` |
| librosa | MFCC算出、YINによるf0推定、STFTユーティリティ | ISC | `>=0.10` |
| matplotlib | スペクトログラム画像の生成（P0-14で使用） | PSF-based（BSD互換） | `>=3.8` |
| jsonschema | 指標出力JSONを `docs/04-metrics.schema.json` に対して検証 | MIT | `>=4.20` |
| pytest | ハーネスのユニットテスト（開発時のみ） | MIT | `>=8.0` |

帯域別指標（Q-004）はいずれのライブラリのmel実装にも依存せず、STFT振幅スペクトルを任意の帯域端（Hz）で直接集計する自前実装とする（上記参照）。これにより等間隔・メル・バークのどれを選んでもライブラリ選定をやり直す必要がない。

- ハーネスのディレクトリ構成・コード自体はP0-02（別Issue）で決める。本ADRは実行環境と依存の確定のみを扱う
