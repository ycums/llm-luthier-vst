# 0003. ゴールデン音源セットの選定とライセンス確認

- **状態**：Accepted
- **日付**：2026-09-05

## 背景

`docs/04-metrics.md` の「ゴールデン音源セット」を確定する（Issue #10）。
このセットは一度確定したら変えられない（変更にはADRを要し、指標履歴が
比較不能になる）ため、選定とライセンス確認を一度にまとめて行う。

このセットは同時に、Q-001（エンジンの合成方式：加算合成かウェーブテーブル
か）の判断材料にもなる。**選定基準に特定の合成方式への有利不利を含めて
いない。** 加算合成に有利な音源（倍音が時間的に大きく動くものだけ）や
ウェーブテーブルに有利な音源（静的なものだけ）に偏らせると、Q-001が観測
ではなく選定によって決まってしまうため、後述の多様性条件（3軸それぞれに
最低3音源）でこれを防いでいる。

## 制約：エージェントは音を聴けない

`AGENTS.md` 第1節により、このADRを書いたエージェントは音を聴いて判断できない。
そのため、各音源の「ピッチの有無」「アタックの鋭さ」「定常部の倍音構成の
時間変化」は、印象ではなく**客観的な信号処理による測定**で判定した。使用
した測定方法と閾値は以下のとおりで、いずれも本リポジトリの正式な指標実装
（`docs/04-metrics.md`、Issue #5〜#9）とは別の、コーパス選定用の簡易スク
リプトによるものである。測定に使った閾値は選定作業のための便宜的な取り決め
であり、指標ハーネス自体の区間境界・閾値（`docs/06-open-questions.md` の
Q-002・Q-004）を先取りするものではない。

- **アタック**：包絡（5msフレームRMS）が最初の顕著な立ち上がり（全体ピーク
  比5%到達点）から、そのローカルピーク（立ち上がり後400ms以内の最大値）の
  10%→90%に達するまでの時間。**≤100msを「鋭い」、それを上回るものを「緩い」**
  とした
- **ピッチの有無**：信号中盤の複数フレーム（60ms窓）における正規化自己相関の
  最大値（50〜1500Hzの遅延範囲、中央値）。**≥0.5を「ピッチあり」**とした
- **定常部の倍音構成の時間変化**：立ち上がり検出後0.5秒をスキップし（アタック
  遷移を避けるため）、続く最大2秒間のスペクトル重心の (最大−最小)/平均。
  **>0.4を「動的」、それ以下を「ほぼ静的」**とした

各エントリの実測値は `corpus/manifest.json` の `diversity.measurements` に
そのまま記録している。この閾値のもとで、想定と異なる結果が出たものは以下の
とおり（推測で埋めず、測定値をそのまま採用した）。

- **スネアドラムのリムショット**（`snare_drum_rim`）：ピッチ強度0.874で
  「ピッチあり」判定になった。リム材（木部）の共鳴による準調的な成分が
  実際に測定されており、「打楽器だから無ピッチ」という思い込みを測定で
  覆した例
- **クラッシュシンバル**（`crash_cymbal`）：アタック立ち上がり約76msで、
  単発の打撃としてはやや緩やかだった。録音にクレッシェンド気味の導入が
  含まれている可能性がある（`corpus/manifest.json` の `known_limitations`
  参照）
- **チベタン・シンギングボウル**（`tibetan_singing_bowl`）：打撃直後の
  倍音構成の動きは比較的小さく「ほぼ静的」側に分類された。長時間録音特有の
  ゆっくりしたビート（うなり）は今回の測定窓（打撃後0.5〜2.5秒）の外側で
  進行するため、この分類は「打撃直後の定常部」に限定した記述である

## 一次情報の扱い

各エントリの `license.text_url` または `license.basis` は、配布元（Wikimedia
Commonsの各ファイル説明ページ）に実際にアクセスして確認したものだけを採用
した。「〜と思われる」「おそらく○○ライセンス」という記述はしていない。

第三者サイト（pdsounds.org）経由の「Public domain」表記を持つ候補は、
2026-09-05時点で配布元サイトが到達不能（HTTP 403、複数回確認）であり、
一次情報を提示できないため、ライセイスの真偽にかかわらずすべて却下した
（下記「却下した候補」参照）。これは「たぶんパブリックドメインだろう」で
済ませないための判断である。

## 検討した案（採用した音源）

11エントリを採用した（`corpus/manifest.json`）。すべてWikimedia Commonsで
配布され、著作権者自身による own-work 表示（自作品としてのライセンス表示）
を伴う。

多様性の検証結果（`corpus/manifest.json` から集計可能）：

| 軸 | 片側 | 件数 |
|---|---|---|
| pitch | yes | 8 |
| pitch | no | 3 |
| attack | sharp | 7 |
| attack | soft | 4 |
| harmonic_motion | dynamic | 8 |
| harmonic_motion | static | 3 |

3軸すべてで両側3音源以上という完了条件を満たす。

`spoken_hello`（人声）を含めた理由：`docs/02-engine-spec.md` のFormant
filter bankは「母音変化」の再現を明示的な要件としており（56行目）、人声の
単語発話はフォルマント軌跡が時間的に大きく動く自然な例として本プロジェクトの
スコープに合致する（`docs/00-vision.md` のNon-goalsは「単一音源分離」を
除外しているだけで、人声を除外していない）。

同梱方針：帰属表示不要（CC0 / PD-ineligible）の3エントリのみをリポジトリに
実体として含めた（`corpus/audio/`、ライセンス原文は `corpus/licenses/`）。
CC BY-SA系の8エントリは、ライセンス上は同梱可能（`bundleable_in_repo: true`）
だが、リポジトリを軽量に保つため取得スクリプト経由の非同梱とした。詳細は
`corpus/README.md`。

## 却下した候補

| 候補 | 却下理由 |
|---|---|
| `File:Sine wave 440.ogg` | `sine_440hz`（`File:440 Sine wave.ogg`）とほぼ同一内容（440Hz正弦波）で、多様性に寄与しない重複 |
| `File:Guitar Standard Tuning.ogg` | 1ファイルに6本の開放弦（別々の音）が連続収録されており、単一の音色イベントではない。客観測定でも「アタック立ち上がり」が9.4秒相当となり、単発ノートの立ち上がりとして測定不能だった。`docs/04-metrics.md` の区間分割（アタック/遷移/定常/リリース）は単一ノートを前提にしており、この構造と整合しない |
| `File:Applause i.ogg`、`File:Gentle breeze and birds singing.ogg`、`File:Old school bell 5.ogg`、`File:Windchime.ogg` | いずれもCommons上は「Public domain」表記だが、根拠が第三者サイト pdsounds.org への参照のみであり、当該サイトは2026-09-05時点で到達不能（HTTP 403）。一次情報を提示できないため却下（「おそらくPD」で済ませない） |
| `File:Pink.Noise.ogg` | 著作権者によるPD-release（自作品の公有化）で来歴自体は明確だったが、ダウンロードした音声データが極端な直流非対称（最小値≈-0.0006、最大値≈1.0）を示し、通常のピンクノイズとして想定される特性と整合しなかった。原因の切り分け（デコード不具合か原盤の問題か）はこのIssueのスコープを超えるため、時間を区切って却下した |
| `File:OneHandClapping.ogg` | 無ピッチな打撃音（拍手）を想定して検討したが、客観測定でピッチ強度0.79と高く出て分類が確定できなかった。疑わしきは採用しない方針で見送った |
| Kalimba de coco (notas sueltas) シリーズ | `kalimba_sample` で同系統（金属タイン撥弦のイディオフォン）を既にカバーしており、追加の多様性への寄与が薄いため見送った |
| MIDIファイル各種 | 記号表現であり波形音声ではない。`docs/04-metrics.md` の指標はレンダ済み波形に対して定義されており対象外 |

## 決定

上記11エントリを `corpus/manifest.json` のゴールデン音源セットとして採用する。

## このセットの変更について

**このセットの構成（エントリの追加・削除・差し替え）を変更する場合は、
必ず新しいADRを書くこと。** `docs/04-metrics.md` の指標履歴はコーパス単位で
蓄積されるため、無断でセットを変更すると過去の指標との比較が不能になる
（`docs/adr/README.md` の要件どおり）。

## 結果

- `corpus/manifest.json`：11エントリのマニフェスト（本ADRの選定結果の実体）
- `corpus/fetch_and_verify.py`：マニフェストのSHA256を検証し、不一致時に
  非0で終了する取得スクリプト（標準ライブラリのみ、`AGENTS.md` 第5節に
  従い新規外部依存を追加していない）
- `corpus/audio/`：帰属表示不要な3エントリの実体
- `corpus/licenses/`：同梱エントリのライセンス原文・根拠
- Q-001（エンジンの合成方式）は、本コーパスの倍音構造の多様性が確保された
  ことで、観測に基づく判断に進める状態になった。ただし判断そのものは
  フェーズ1のエンジン実装後に行うため、`docs/06-open-questions.md` の
  Q-001は本ADRでは resolved にしない
