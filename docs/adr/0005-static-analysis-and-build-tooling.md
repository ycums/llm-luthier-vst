# 0005. 静的解析（ruff）と環境構築（uv）の採用

- **状態**：Proposed
- **日付**：2026-09-05

## 背景

`AGENTS.md` 第8節の「3回ルール」（同じ種類の失敗・手戻りが3回起きた時点でCIチェック追加やスキル化を提案する）は、**linter が未導入のためカウント手段そのものが存在せず、運用不能（死にルール）** だった。同節の「実装より先にCIチェック項目やスキルを書き起こすな」という禁止事項と整合させるには、「実際に何度も壊れる」観測が前提になるが、lint 違反はCIや人の目で検出されない限り記録にも残らない。

また、リポジトリにCI（`.github/workflows/`）が存在せず、lint 違反が未検出のまま累積していた（導入時点で14件検出）。

## 検討した案

### 静的解析ツール

#### 案A：ruff（採用）
- 利点：単一バイナリでlint・format・import整理を担う。デフォルトルールが充足しており、初期設定の手間が最小。Python 3.11のターゲットにも対応
- 欠点：ruff 0.16で「デフォルトのルール」が旧来の `E4/E7/E9/F` から大幅に拡大し（`I/UP/RUF` 等が追加）、意図せず厳しくなる。対策は後述のマイナーバージョン固定

#### 案B：flake8
- **却下理由**：import順・format等を別ツール（isort/black）に委譲する必要があり、複数ツールの設定管理が増える。ruff一択で済む

#### 案C：pylint
- **却下理由**：設定が複雑で重く、デフォルトで大量のノイズが出る。小〜中規模コードベースに合わない

#### 案D：mypy（静的型検査）
- **却下理由**：型検査はlintとは別の目的。本リポジトリは `harness` のみで規模が小さく、型注釈規律の導入は段階的に行うべき。本ADRではlint導入に留める

### 環境構築・依存管理

#### 案E：uv（採用）
- 利点：依存解決・仮想環境作成・`pyproject.toml`管理を単一コマンドで行える。`uv.lock` による再現性があり、CI とローカルの環境を一致させやすい。pip と比べて依存解決が速い
- 欠点：uv に依存する（uv 未導入の環境では `pip install -e .[dev]` でも代替可能で、破壊的ではない）。lock ファイルが大きい

#### 案F：pip + requirements.txt
- **却下理由**：再現性の担保が弱く（lockを手動管理）、CIとローカルの差が出やすい。uv のほうが整合性が取れる

## 決定

### 静的解析

**ruff**（案A）を dev 依存として導入する。`pyproject.toml` の `[tool.ruff]` に `target-version = "py311"` のみを設定し、**ルールセットは明示指定せず ruff 0.16 のデフォルトに従う**。

- ルールセットを明示的に固定しないのは、`AGENTS.md` 第8節「先回りして環境を整えない」、および「実際に何度も壊れることを観測してから初めてルールを追加・調整する」という方針と整合させるため。
- ただし ruff 0.16 でデフォルトが拡大した経緯を踏まえ、**マイナーバージョンで固定**（`ruff>=0.16,<0.17`）し、CI とローカルの挙動を一致させる。将来デフォルト拡大に伴う違反増は、3回ルールの観測対象として扱う。

### 環境構築

**uv**（案E）を環境構築・依存管理の標準とする。CI では `uv sync --extra dev` を使用する。

### CI

`.github/workflows/ci.yml` で `ruff check .` と `pytest -q` を実行する。ローカルでは `uv run ruff check .` / `uv run pytest -q` で同一挙動を保証する。

## 結果

- `pyproject.toml` に `ruff` を dev 依存として追加し、`[tool.ruff]` 設定を記述した
- 導入時点で検出された lint 違反（全ファイル計。`RUF100`/`I001`/`UP035`/`RUF007`/`RUF022`/`RUF046`/`F401`/`F841`）を解消した
- CI で `ruff check` + `pytest` が green になることを確認した

## 今後の対象

- ルールの追加・調整（3回ルールの観測を根拠として）は、今後の課題として `AGENTS.md` 第8節の方針に従う。本ADRは「デフォルトから始め、必要に応じて変える」という初期方針だけを確定する
- 型検査（mypy等）の導入は本ADRのスコープ外。別途検討する
- エンジン本体（フェーズ1、C++等）は本ADRの対象外。ハーネス（Python）のみ
