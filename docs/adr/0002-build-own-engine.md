# 0002. 既存プラグインの自動操作ではなく自前エンジンを持つ

- **状態**：Accepted
- **日付**：2026-09-05

## 背景

「音源からパラメータを推定してシンセを鳴らす」を実現する手段は複数ある。

## 検討した案

### 案A：既存の市販プラグインをLLMが自動操作する
- 利点：音質・機能が既に成熟している。開発量が小さい
- **却下理由**：プラグインごとにパラメータ体系が異なり、写像を個別に作る必要がある。多くはパラメータの外部からの一括書き換え経路が保証されておらず、ヘッドレスレンダも成立しにくい。何より、残差から「エンジンの能力を改訂する」というループ2が原理的に回せない

### 案B：ニューラル音声生成（RAVE等）でティンバー転写する
- 利点：再現度が高い
- **却下理由**：出力がブラックボックスであり、DAWで操作可能なパラメータとして露出できない。`docs/00-vision.md` の水準2を満たせない

### 案C：自前のシンセエンジンを持つ（採用）
- 利点：パラメータ空間を自分で設計でき、ループ2で改訂できる。ヘッドレスレンダを同一コアから作れる。DAW露出軸を意図して設計できる
- 欠点：開発量が最も大きい。音質は自力で作り込む必要がある

## 決定

案Cを採用する。ループ2（エンジン能力そのものの改訂）が本プロジェクトの中核であり、これを回せない案は目的を達成できない。

## 参考にする先行実装

- **Sonic Charge Synplant 2 / Genopatch**：サンプルからFM系エンジンのパラメータを探索する商用実装。エンジン側の自由度をどう設計したかの参考
- **Google Magenta DDSP**：微分可能シンセをオーディオにフィッティングする。推定手法の参考
- **RAVE**：案Bとして却下したが、比較対象として位置づけを把握しておく

## 結果

- 開発量が大きいため、フェーズを刻んで進める（`docs/00-vision.md`）
- エンジンコアはプラグインフレームワークから独立させる必要がある
