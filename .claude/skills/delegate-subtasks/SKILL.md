# delegate-subtasks

親セッションから、指定したセッションIDのセッションへ「サブタスクを
消化してほしい」という依頼を送るSkill。対象セッションがローカルの
場合は、依頼に先立って専用のgit worktreeを新規作成し、対象セッション
がそこへ切り替えて作業できるようにする。対象がリモートセッションの
場合、worktreeはリモート側で独立して管理されるためこのSkillでは
何も構成しない。

## 引数

- 第1引数: 依頼先セッションのセッションID（必須）。
  `mcp__ccd_session_mgmt__list_sessions` で一覧を確認するか、対象セッション
  側で `/nop` を実行して得られたIDを使う。

引数が渡されていない場合は、ユーザーに対象セッションIDを尋ねる。

## 手順

1. 渡されたセッションIDが自分自身（現在のセッション）のIDと一致しない
   ことを確認する。一致する場合はエラーとしてユーザーに伝える。
2. `mcp__ccd_session_mgmt__get_session` で対象セッションの情報を取得し、
   実在すること・アーカイブされていないことを確認する。同時に
   `isRemote` フィールドを確認する。
   - 存在しない/アーカイブ済みの場合はユーザーに報告して中断する。
3. **`isRemote: false`（ローカルセッション）の場合のみ**、専用のworktreeを
   用意する:
   a. 現在（親セッション）がgitリポジトリ内で作業していることを確認する。
      そうでなければユーザーに報告して中断する。
   b. `git worktree add <path> -b <branch>` (Bash) で、対象セッション専用の
      新しいworktreeを作成する。パス・ブランチ名は対象セッションIDや
      タイトルから一意に識別できるものにする
      （例: `.claude/worktrees/delegate-<session_id短縮形>`)。
      親セッション自身はこのworktreeには切り替えない
      （`EnterWorktree` は親では使わない。切り替わるのは対象セッション側）。
   c. 作成したworktreeの絶対パスを控えておく。
   - `isRemote: true`（リモートセッション）の場合はこの手順3全体を
     スキップする。
4. `mcp__ccd_session_mgmt__send_message` で対象セッションIDへ依頼メッセージ
   を送る。内容:
   - ローカルセッションの場合: 手順3で作成したworktreeの絶対パスを伝え、
     まず `EnterWorktree`(`path: "<そのパス>"`) でそこへ切り替えてから、
     残っているサブタスクを1つずつ消化してほしいこと
   - リモートセッションの場合: worktreeの案内は行わず、そのまま残っている
     サブタスクを1つずつ消化してほしいこと
   - （共通）サブタスクがなくなるまで繰り返し、完了したら結果を要約して
     報告してほしいこと。作業中に判断に迷うものがあれば報告に含めてよい
     こと。
5. 送信結果（成功したこと、対象セッションのタイトル、ローカルの場合は
   作成したworktreeのパス）をユーザーに簡潔に報告する。

## 注意

- `send_message` は unattended セッション（スケジュール実行・remote
  dispatch されたセッション）には配送できない。対象がそれに該当する
  場合はユーザーに伝える。
- worktreeの新規作成は破壊的操作ではないが、対象リポジトリの状態に
  依存する。作成に失敗した場合はエラー内容をそのままユーザーに伝え、
  メッセージ送信は行わない。
